# Python 中的多态：实现方式与使用场景

> 章节：chapter04 · 面向对象进阶
> 前置知识：chapter01（`type` / `isinstance`）、chapter04（`classmethod` / `staticmethod`，"多态工厂"即 cls 跟随调用者的多态体现）

## 一句话结论

**多态 = 同一段代码，对不同类型的对象表现出不同的行为。** Python 是动态类型语言，多态主要靠**鸭子类型 + 运行时动态分发**天然实现：调用方只关心"对象有没有这个能力"，不关心"对象是什么类型、有没有继承关系"。

---

## 1. 核心机制：动态分发与鸭子类型

- **动态分发（dynamic dispatch）**：`x.method()` 执行时，运行时按 `x` 的**实际类型**（沿 MRO）查找并调用对应方法，由解释器自动完成。
- **鸭子类型（duck typing）**："如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。" 不要求显式接口或继承，只要对象具有所需方法/属性即可。

```python
def make_sound(animal):
    animal.speak()   # 只要求对象有 speak()，调用时才真正绑定

class Dog:
    def speak(self): return "Woof"

class Cat:
    def speak(self): return "Meow"

class AlarmClock:                # 与 Dog/Cat 毫无继承关系，也能"多态"
    def speak(self): return "Beep! Beep!"

make_sound(Dog())          # Woof
make_sound(Cat())          # Meow
make_sound(AlarmClock())   # Beep! Beep!
```

`AlarmClock` 与 `Dog` 没有共同基类，调用方无感——这就是 Python 式多态与 Java/C++ 的差别：**多态不依赖继承体系**。

## 2. 五种实现方式

### 2.1 鸭子类型（默认、最 Pythonic）

见第 1 节示例。适用于原型开发、快速迭代、追求灵活性。

- 优点：零样板代码，任何对象即插即用。
- 缺点：契约隐式，方法名拼错要运行时才暴露。

### 2.2 继承 + 方法重写（经典 OOP）

基类定义接口/默认行为，子类重写。

```python
class Animal:
    def speak(self):
        return "..."

class Dog(Animal):
    def speak(self):
        return "Woof"

class Cat(Animal):
    def speak(self):
        return "Meow"

animals = [Dog(), Cat()]
for a in animals:
    a.speak()   # 基类视角调用，运行时分发到子类实现
```

- 优点：结构清晰、可复用基类实现、`isinstance` 检查友好。
- 缺点：需要继承体系，灵活性低于鸭子类型。

### 2.3 抽象基类 ABC（显式契约，框架场景推荐）

用 `abc.ABC` + `@abstractmethod` 强制"必须实现"的接口。

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    @abstractmethod
    def speak(self) -> str: ...

class Dog(Animal):
    def speak(self):
        return "Woof"   # 不实现的话无法实例化（TypeError）
```

- 与 `isinstance` 配合：`isinstance(d, Animal)` 为 True（见 chapter01），适合"接口即类型"的场合。
- 注意：ABC 约束的是**继承体系内**的契约，拦不住鸭子对象混入——`AlarmClock` 不继承 `Animal` 也能被 `make_sound` 调用。

### 2.4 Protocol（结构化子类型，Python 3.8+）

静态检查层面的"接口约定"：只定义形状，不要求继承。

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Speaker(Protocol):
    def speak(self) -> str: ...

def make_sound(animal: Speaker) -> None:   # 静态检查：结构符合即可
    animal.speak()
```

- 配合 mypy / pyright 做静态检查；`@runtime_checkable` 允许运行时 `isinstance` 检查。
- 适合库作者定义"协议"，同时保持鸭子类型的灵活性。

### 2.5 特殊方法（操作符多态）

通过 dunder 方法让 `+`、`len()`、`[]` 等内建操作对不同类型表现出不同行为。

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):           # 让 + 支持自定义类型
        return Vector(self.x + other.x, self.y + other.y)

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

Vector(1, 2) + Vector(3, 4)   # Vector(4, 6)
```

## 3. 实现方式对比表

| 方式 | 是否需要继承 | 契约强度 | 静态检查 | 典型场景 |
|---|---|---|---|---|
| 鸭子类型 | 否 | 隐式 | 无 | 原型、灵活扩展 |
| 继承重写 | 是 | 隐式（基类约定） | 无 | 经典 OOP、可复用基类 |
| ABC | 是（必须继承） | 强（抽象方法） | 部分（mypy） | 框架接口、强制契约 |
| Protocol | 否（结构匹配） | 中（结构化） | 强（mypy / pyright） | 库作者定义协议 |
| 特殊方法 | 否 | 隐式 | 无 | 运算符重载、容器类型 |

## 4. 使用场景

1. **策略模式**：同一接口、不同算法，运行时切换。

   ```python
   class SortStrategy:
       def sort(self, data): ...
   class QuickSort(SortStrategy):
       def sort(self, data): ...
   class MergeSort(SortStrategy):
       def sort(self, data): ...
   ```

2. **多后端适配**：存储后端（MySQL / Redis / 内存）、通知渠道（短信 / 邮件 / Webhook）——调用方只依赖接口，实现可整体替换。
3. **依赖倒置**：高层模块依赖抽象，不依赖具体实现（FastAPI 依赖注入天然支持）。
4. **框架扩展点**：用户通过继承 / 重写 / 实现协议扩展框架行为（FastAPI 中间件、Pydantic validator 均属此类）。
5. **测试替身**：Mock / Stub 对象只需有相同方法签名即可替换真实依赖（鸭子类型让测试极简）。

## 5. 与静态语言（Java / C++）的对比

| 维度 | Java / C++ | Python |
|---|---|---|
| 多态前提 | 继承或接口，基类/接口引用指向子类 | 无需继承，只要对象有对应方法 |
| 分发时机 | 运行期虚函数表（或编译期重载） | 运行期按实际类型查 MRO（动态分发） |
| 类型约束 | 编译期强制 | 运行时弱约束（可用 isinstance / Protocol 加强） |
| 灵活性 | 低（需先设计接口体系） | 高（即插即用） |
| 可维护性 | 高（契约显式、IDE 提示强） | 依赖自律，或用 ABC / Protocol 补契约 |

## 6. 常见坑

1. **方法名不一致**：鸭子类型下拼错方法名（如 `spak`）运行时才报 `AttributeError`——代码规模变大后建议用 ABC / Protocol 显式化契约。
2. **isinstance 检查与鸭子类型的张力**：频繁 `isinstance` 检查会削弱多态的开放性；先问"我要的是能力还是类型"（对应 chapter01 的 `type` vs `isinstance` 选型）。
3. **LBYL vs EAFP**：别用 `hasattr` 反复探测能力，Python 惯例是直接调用、用 `try/except` 兜底。
4. **ABC 不约束鸭子**：ABC 只管继承体系内；要约束"结构"用 Protocol。
5. **重写方法时记得 super()**：子类重写若需保留基类行为，显式 `super().method()`，否则基类逻辑被静默覆盖。

## 7. 与 FastAPI 的关联

- **依赖注入**：`Depends` 不关心具体类型，任何可调用/可实例化对象都能注入——鸭子类型在框架层的体现。
- **多实现切换**：按环境注入不同后端（`get_db` 返回 MySQL 或内存实现），调用方代码不变。
- **Pydantic validator**：基于 classmethod 语义的扩展点（见上一章），子类重写 validator 即"方法重写式多态"。

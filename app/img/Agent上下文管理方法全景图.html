问题来源
Agent 会话持续增长
工具调用记录、多轮对话、检索结果不断累积
→
硬约束
LLM 上下文窗口有限
超窗即截断/报错，成本随 token 数上升
核心目标：在有限窗口内，以最小代价保留对后续决策最高价值的信息 —— 5 大类常用策略如下
族 1 直接丢弃 最省事，只解决"超窗"，不解决"失忆"
① 滑动窗口 / 截断
只保留最近 N 轮消息或 N 个 token，其余直接丢弃
实现简单 · 零开销 · 可控性强 早期目标/约束/用户偏好全丢
典型实现：API 层按时间/条数裁剪消息数组；适合短会话、一次性任务
族 2 压缩提炼 用更少 token 保住语义主线
② 滚动摘要
旧对话先让 LLM 压成一段摘要，摘要+新消息一起进入窗口
保留主线 · 支持长对话 细节/数字有损 · 摘要可能失真
典型实现：LangChain ConversationSummaryMemory；适合叙事型、目标型长对话
③ 结构化记忆提取
实时抽取实体、偏好、事实，写入画像/知识库，用时回填
精准 · 跨会话复用 抽取有损 · 需维护更新
典型实现：用户画像/属性表、知识图谱；适合个性化助手、长期陪伴场景
族 3 检索召回 按需取回，不占窗口常驻
④ 向量检索（RAG 式记忆）
历史消息/知识切块向量化入库，根据当前 query 语义相似度召回 Top-K 注入
精确找回细节 · 可扩展 需向量库/embedding · 检索质量不稳
典型实现：向量数据库 + 重排序；适合知识密集、需引用旧事实的 Agent
族 4 分级管理 把窗口当"内存"来设计
⑤ 虚拟内存换页（MemGPT/Letta 式）
主上下文=工作内存，外部存储=磁盘；按需把旧块换出/换入，像 OS 管理内存
窗口利用率高 · 支持超长会话 实现复杂 · 换页策略难调
典型实现：Letta/MemGPT 框架；适合多任务、持续运行的 Agent
⑥ 重要性/优先级修剪
给每条消息按重要性、时效性、相关性打分，低分先淘汰
保高价值信息 · 可控 打分规则难设计 · 可能误杀
典型实现：LLM 打分/启发式规则混合；适合工具调用密集的复杂 Agent
族 5 隔离分工 不让单个窗口扛全部记忆
⑦ 多 Agent 上下文隔离
子 Agent 各自维护独立上下文，主 Agent 只接收结构化结果/摘要
防上下文污染 · 可并行扩展 传递有损 · 编排成本高
典型实现：CrewAI/AutoGen/本系统 MoA 架构；适合分工明确的大型任务
工程实践：生产环境多为组合拳
兜底层：滑动窗口限长，防超窗崩溃 主线层：滚动摘要 + 结构化记忆，保目标与偏好 细节层：向量检索按需召回关键事实
选择口诀：会话短→窗口裁剪；会话长→加摘要；要记细节→加检索；要跑复杂任务→分级或拆 Agent。
